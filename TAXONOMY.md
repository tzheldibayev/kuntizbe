# Карта налоговых событий РК

Рабочий документ. Определяет **структуру** — по каким осям налогоплательщик классифицируется и какие типы событий существуют.

Конкретные номера форм и сроки в таблицах отмечены как непроверенные и заполняются из первоисточников. Новый Налоговый кодекс действует с 1 января 2026 года, нумерация и сроки могли измениться относительно любых вторичных публикаций.

---

## 1. Оси категоризации

Режим — не плоский список, а точка в пространстве нескольких независимых признаков. Из этого следует структура конфига подписки.

### Ось A — организационная форма

| Значение | Комментарий |
|---|---|
| `individual` | физлицо без предпринимательской деятельности |
| `self-employed` | самозанятый, без регистрации ИП |
| `ip` | индивидуальный предприниматель |
| `too` | юридическое лицо |
| `kfh` | крестьянское / фермерское хозяйство |

### Ось B — налоговый режим

С 2026 года: общеустановленный порядок плюс три специальных режима.

| Значение | Комментарий |
|---|---|
| `our` | общеустановленный |
| `snr-self-employed` | СНР для самозанятых — заменил патент и мобильное приложение |
| `snr-simplified` | СНР на основе упрощённой декларации — вобрал признаки розничного налога |
| `snr-farm` | СНР для КФХ — **уточнить точное наименование в ст. 715** |

### Ось C — НДС

| Значение |
|---|
| `vat-none` |
| `vat-registered` |

Ставка с 2026 года — 16%. Порог обязательной постановки на учёт — 10 000 МРП.

### Ось D — наёмный труд

| Значение | Следствие |
|---|---|
| `no-employees` | только обязательства за себя |
| `has-employees` | плюс удержания и перечисления за работников, ежемесячный ритм |

### Ось E — активы и особые обстоятельства

Каждый признак включает свой набор правил независимо от остальных осей.

| Признак | Значение |
|---|---|
| `property` | налог на имущество |
| `vehicle` | налог на транспорт |
| `land` | земельный налог |
| `foreign-trade` | ВЭД, импорт/экспорт |
| `non-resident-payments` | выплаты нерезидентам |

## 2. Как оси превращаются в фид

Конфиг подписки хранит **позицию по осям**, а не итоговый набор правил.

```json
{
  "form": "ip",
  "regime": "snr-simplified",
  "vat": "vat-none",
  "employees": "has-employees",
  "flags": ["vehicle"]
}
```

Разрешение «оси → набор правил» происходит **при каждой генерации**, а не при подписке. Появилась новая форма отчётности — все подходящие подписчики получают её автоматически. Замороженный при подписке список правил означал бы, что человек никогда не узнает о новом обязательстве.

Правило объявляет условия применимости:

```yaml
applies_when:
  form: [ip, too]
  regime: [our, snr-simplified]
  vat: [vat-registered]
```

## 3. Типы событий

Три разных типа. Смешивать их в одну сущность нельзя — у них разная механика и разная цена ошибки.

### Тип 1 — Сдача отчётности

Подача ФНО. У части форм есть окно: раньше определённой даты подать нельзя.

```
DTSTART = открытие окна (или дата дедлайна, если окна нет)
DTEND   = дедлайн
```

### Тип 2 — Уплата налога

**Отдельное событие с отдельной датой.** Срок уплаты, как правило, не совпадает со сроком сдачи декларации.

Это самый недооценённый тип. Просрочка платежа даёт пеню независимо от того, сдана ли декларация вовремя. Человек, который считает, что «сдал и свободен», получает начисления.

Каждое правило типа 1 требует явной проверки: есть ли у него парное правило типа 2 и на какую дату.

### Тип 3 — Социальные платежи

ОПВ, ОПВР, социальные отчисления, ОСМС, ВОСМС, социальный налог.

Ежемесячный ритм, единая дата для большинства платежей. Применяются и за себя, и за работников — при `has-employees` набор шире.

Технически это подмножество типа 2, но выделяется отдельно: у них своя периодичность и они касаются практически всех, включая самозанятых.

---

## Граница продукта

**Сервис отвечает за даты. Налогоплательщик отвечает за факты о себе.**

В фид попадает только то, что является календарным сроком, установленным нормой, известным заранее и одинаковым для всех в пределах режима.

Не попадает ничего, зависящего от цифр конкретного пользователя: достижение порога регистрации по НДС, утрата права на спецрежим при превышении лимита, любые напоминания «проверьте свой оборот». Отслеживание состояния налогоплательщика превращает календарь в учётную систему с ответственностью за чужие данные.

Проверка при добавлении любого нового правила: это дата из кодекса — да; это зависит от того, что человек о себе знает — нет.

## 5. Порядок заполнения

Первыми кодируются правила, покрывающие наибольшую долю аудитории при наименьшем числе правил:

1. `self-employed` — минимальный набор, и это твой собственный статус;
2. `ip` + `snr-simplified` + `no-employees` — самая массовая конфигурация;
3. `ip` + `snr-simplified` + `has-employees`;
4. `vat-registered` — аудитория, выросшая после снижения порога;
5. `too` + `our` + `vat-registered`;
6. флаги из оси E.

- [ ] Точный перечень и наименования трёх СНР по ст. 715
- [ ] Сохранилась ли нумерация ФНО под новым кодексом
